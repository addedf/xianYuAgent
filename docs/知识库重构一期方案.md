# 知识库重构一期方案：生效闭环 + 生效规则总账

> 状态：**一期实现中**（2026-09-25 用户已确认执行；代码、迁移与自动检查已落地，真实线索端到端验收待做）
> 范围：本期只做「让知识生效 + 全量可见」最小闭环；批量导入导出放二期。

## 一、实施前背景诊断（为什么重构）

评分链路真正消费的知识/规则分三层，页面只覆盖了三分之一：

| 层 | 内容 | 现状 |
|---|---|---|
| 数据库规则（3 条） | 卖家阈值、高仿词表、价格比例 | 可见、版本化，但**只有卖家阈值能编辑**（高仿词/价格比例连编辑 API 都没有）；`enabled=false` 的语义是「回退代码默认值」，不是真停用 |
| 代码内嵌知识 | `facts.ts` 四组词表（个人叙事/序列号/凭证/附件）+ 阈值（模板相似度 0.72、集中度 3 条/0.75、文案 35 字、图片 5 张、价差 0.18）、`finalize.ts` 总分权重与动作阈值、`questions.ts` JEV 指令与 rubric | **页面完全不可见**，是真正的黑箱；AI 维护的规则基本都改在这一层 |
| 知识条目 | 鉴别点 / 卖家信号 / 价格经验 / 沟通追问 / 案例 | 可见可编辑，但**评分链路零消费**（`knowledge_entries` 只被知识页读取），「规则引用 0 次」是硬编码 `usageCount: 0`，纯属存档 |

关键链路事实（已核实）：

- 三个生产评分调用点（采集持久化 `xianyu-spider-persistence.ts:401`、单条重评分 `rescore/route.ts:61`、试算 `assess/route.ts:74`）都经过 `evaluateListing → buildTypesafeState`，在这一个点注入知识即可全覆盖。
- `scoredAssessmentFingerprint`（`xianyu-spider-persistence.ts:53`）目前不含知识维度——不补上，知识改了之后重评分会被「已评分」检查直接跳过。
- `suggestedQuestions`（沟通追问）没有持久化也无处渲染，是读取时从缺失清单重新生成的（`listings.ts:56`）。
- 证据行来源标签已含 `knowledge: "知识"`（`lead-workbench.tsx:39`），知识类证据可以直接复用现有线索详情 UI。

## 二、已确认的方向（2026-09-25 讨论结论）

1. **生效方式：按类型分流。** 鉴别点/沟通追问/价格经验注入 JEV 上下文（软生效）；卖家信号沉淀为词表规则（硬生效，三期做词表化，本期先随上下文注入）。
2. **批量维护形态：Web 导入导出。** 导出 Markdown 正本 → AI 修改 → 粘贴导入 diff 预览 → 批量草稿入库 → 人工复核转正（二期实现）。
3. **一期范围：生效闭环 + 总账一起做。**

## 三、一期实施计划

### 1. 数据模型（迁移 0004）

- `knowledge_entries` 加 `effect_channel text not null default 'manual-only'`（生效通道：jev-context / manual-only）。存量条目先保持仅存档；新增非案例条目可选择 JEV 通道，但都需人工批准后才生效。
- `assessments` 加 `knowledge_used jsonb not null default '[]'`（记录每次评分注入了哪些知识条目）。
- 价格过滤的真实数据输入同步纳入迁移与服务端契约：参考价观察/审批记录、商品当前匹配结果、评估时参考价快照，字段与准入条件见 [市场参考价来源与落库方案](./市场参考价来源与落库方案.md)。无合格参考价不得虚构默认价格。
- 0004 迁移创建审批与参考价字段、参考价版本表和手动评估运行记录；0005 补商品当前参考价 ID；0006 记录规则版本的人工或 AI 辅助来源；0007 保存逐条价格样本；0008 补可比成色、年份、附件和市场字段。案例类默认仅存档，存量知识不自动批准。
- `scripts/dev-mac.sh start` 自动应用迁移。

### 2. 领域层（纯函数 + 测试）

- 新 `src/domain/knowledge-context.ts`：确定性知识筛选——
  - 匹配：品类相等；品牌为空 = 通用品类，否则与线索品牌忽略大小写精确匹配；型号非空时也须精确匹配，避免宽泛词误注入；
  - 仅选 active、已批准、jev-context 且非案例条目；排序 verified > reviewed > draft，再按型号、品牌明确程度和更新时间；
  - 预算：总条数上限 10、总字符约 6000；
  - `knowledgeHash`：对入选集合（"id:version" 排序拼接）做 sha256，供评分指纹使用；
  - 输出保留类型，JEV state 按 identification / pricing / question / seller-signal 分组（case 不注入）。
- 新 `src/domain/rule-registry.ts`：声明全部生效项（code、链路阶段、当前值、来源、影响说明、是否可编辑），覆盖 3 条 DB 前置规则、`facts.ts` 词表与阈值（个人叙事词/序列号词/凭证词/附件词、模板相似度 0.72、集中度 3 条/0.75、文案 35 字、图片 5 张、事实层价差 0.18）、`finalize.ts` 权重与动作阈值、JEV 指令版本/置信度阈值/限频、知识注入统计（动态）。
- `listing.ts`：`KnowledgeEntry` 加生效通道、复核状态和录入来源；`ListingAssessment` 加可选 `knowledgeQuestions`。
- `pre-filters.ts`：`PreFilterConfigs` 三项支持 null=停用，`runPreFilters` 跳过对应检查。

### 3. 服务端

- 新 `src/server/knowledge-injection.ts`：`loadActiveKnowledgeEntries()`（active + channel=jev-context，一次查询）；批处理路径整批加载一次、逐线索 scope。
- `questions.ts`：`buildTypesafeState` 增加第 4 参知识上下文，state 增加 `domainKnowledge` 分组字段（文本过 `publicText` 脱敏）；instruction 增加说明：知识是人工维护的参考经验、不是已核验事实、与商品文案冲突时以文案为准；`QUESTIONS_VERSION` → v6。
- `evaluateListing` options 增 `knowledge`，三个调用点传入：
  - 持久化路径：批量加载一次；`scoredAssessmentFingerprint` 增加 `knowledgeHash` 参数；`assessmentValues` 写 `knowledge_used`；注入非空时在 evidence 追加一行 `source:"knowledge"` 的「知识上下文」证据（helper `withKnowledgeEvidence`）；
  - rescore / assess 路由：同样注入并写 `knowledge_used`（assess 为试算不落库）。
- `listings.ts`：线索列表每页一次查询取 active question 条目，读时按品类/品牌挂到 `assessment.knowledgeQuestions`（不动 schema、不影响指纹）。
- `knowledge.ts`：用 `jsonb_array_elements_text(knowledge_used)` 聚合出真实 `usageCount`（= 当前评估记录的引用条数；重复手动运行次数另见 `assessment_runs`）。
- 新 `app/api/knowledge/pipeline-rule/route.ts`：POST 保存高仿词表（terms）或价格比例（priceRatioBelow），沿用 seller-rule 的事务版本化模式；PATCH 切换 enabled。停用改真语义：加载器区分「无行=默认启用」与「有行 enabled=false=停用」（配置置 null；seller 停用时不下发 `sellerRuleThresholds`）。
- `app/api/knowledge/route.ts`：创建/更新支持 `effectChannel`，录入和修改进入待复核，批准后可生效；AI 辅助内容可标注 `ai-assisted` 并在后台查看。
- 价格比例规则的真实数据前提见 [市场参考价来源与落库方案](./市场参考价来源与落库方案.md)：参考价需有可比来源、人工确认、持久化与评估快照；无合格参考价时，该过滤器跳过并在总账说明实际状态。

## 四、行为变化与注意

- `QUESTIONS_VERSION` v6 + 指纹含知识 hash：版本变化后可由用户选择全量重新评分。自动扫描对输入未变化的商品复用已有评估；用户明确触发单条/全量重新评分时可再次调用 JEV，并应保留重复运行的历史与原因，不能静默覆盖旧评分。
- JEV 每次调用 prompt 增加约 ≤6000 字符知识上下文；限频 30/min 不变。
- 知识只作参考上下文注入，不替代 rubric 判断，也不直接改分数——符合 DESIGN.md「Agent 不自动覆盖人工规则」「所有经验升级必须有版本与批准记录」。
- 事实层 0.18 价差与前置过滤 0.18 目前是双源，总账会分别如实展示，统一留待后续。
- 隐私约束不变：知识文本发给 JEV 前过 `publicText` 脱敏；不写入任何 Cookie/Token。
